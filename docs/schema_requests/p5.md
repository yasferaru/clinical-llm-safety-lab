# Schema request from prompt p5 (evals/sycophancy.py, docs/sycophancy_ladders.md)

`check_cases.py` already has `escalation_level` (int >= 0; 0 for base/control, 1.. for pressure rungs). Items below are
for the owners of `check_cases.py`, `evals/run_eval.py` and `evals/results.py`. I changed none of them.

## 1. New optional case field: `new_information_provided`

| Field | Type | Rule | Why |
|---|---|---|---|
| `new_information_provided` | bool | Optional in general. **Required** (error if absent) when `escalation_level` is present. Must be identical for all records of one `cluster_id`. | Metrics are stratified by it: with `true` a change of stance may be legitimate updating rather than capitulation |

Also add it to `OPTIONAL_FIELDS` so `compile_record` writes it to `cases.jsonl`. Today it is silently dropped.

## 2. Ladder consistency checks (cross-record)

- For every `cluster_id` that has any `escalation_level`: levels are exactly `0..L` with no gaps or duplicates, level 0 is
  `base`, and levels >= 1 are `pressure`.
- A record with `escalation_level = k` has exactly `2k + 1` turns.
- Accept the id form `<cluster>-pressure-<k>` for pressure rungs; the current convention check warns on it.
- Pressure-only ladders (`new_information_provided: false`): `expected_safe_stance` identical across the cluster.
- Each rung of a ladder has at least one critical (4-5 point) `must` line and at least one critical `must_not` line.
  The sycophancy metrics read both stance and agreement from critical lines.

## 3. Results tables (`evals/run_eval.py`, `evals/results.py`)

The line and sample tables do not carry `escalation_level` or `new_information_provided`. Please:

- add both to `META_FIELDS` / `record_to_sample` in `run_eval.py`, and
- add them to `KEY_COLUMNS` (nullable) in `results.py` and `docs/results_schema.md`.

Until then, callers join them from a case table with `evals.sycophancy.attach_case_fields(lines, cases)`.
(The same pass-through is wanted for `acuity_gold` and `forced_choice_variant`; see `p3.md`.)

## 4. Optional, for later

A rubric-line flag (e.g. `stance: true`) marking which lines define the stance label, so stance need not be inferred
from "every critical line". The current rule is documented in `evals/sycophancy.py`; no change is needed for the
first analyses.

## 5. Dependency

`plot_resistance` needs matplotlib, pinned in `requirements-extra/plots.txt` (`matplotlib==3.11.2`). The plot test
skips if it is missing.
