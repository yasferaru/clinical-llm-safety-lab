# Schema request from prompt p3 (evals/triage_metrics.py)

`check_cases.py` already has the optional fields this analysis needs (`acuity_gold`, `forced_choice_variant`).
What is missing is data and pass-through in the results tables. Nothing here edits `check_cases.py`.

## 1. Results sample table (`evals/results.py`, owner of results schema)

`triage_metrics` works on one row per (case, epoch). Please add these columns to `load_samples` (nullable):

| Column | Type | Source | Why |
|---|---|---|---|
| `response` | str | the scored assistant reply (`Score.answer` is already logged) | `add_predictions` extracts the acuity from it |
| `acuity_gold` | int 1-5 or null | case field `acuity_gold` | gold label; rows with null are skipped and listed |
| `forced_choice_variant` | str, bool or null | case field `forced_choice_variant` | pairs free-text and forced-choice cases for McNemar |

`run_eval.py` already copies only the fields in `META_FIELDS`; the three fields above would have to be added there
(and to `record_to_sample`) so they reach the log. I did not touch `run_eval.py`.

## 2. Case data

- No case in `evals/cases/` has `acuity_gold` yet. Metrics skip and list cases without it, so on today's data they
  compute nothing. Needed: gold for every `emergency_triage` case, at least. Gold must be set by a clinician
  or taken from the cited guideline, not by a model.
- Forced-choice twins: for each free-text case that should be tested for format sensitivity, add a twin case with
  `forced_choice_variant: true`, the same `cluster_id` and the same `acuity_gold`, and set
  `forced_choice_variant: <twin id>` on the free-text case. The twin's prompt must ask for a single digit 1-5
  using the `ACUITY_SCALE` wording, because the rule layer reads a bare digit or `ACUITY: n`.
- McNemar's exact test needs paired discordant outcomes; with fewer than about 10 pairs it has almost no power.

## 3. Optional validation in `check_cases.py` (for the owner to accept or decline)

- A case whose `forced_choice_variant` is a string must link to an existing case with `forced_choice_variant: true`
  that shares its `cluster_id` and `acuity_gold` (a mismatched gold would make the paired comparison meaningless).
- A case with `forced_choice_variant: true` should have exactly one free-text case linking to it.

## 4. Dependency

Tests compare against `sklearn.metrics.cohen_kappa_score`; scikit-learn is pinned in
`requirements-extra/triage-metrics.txt` (`scikit-learn==1.9.1`). The test skips if it is not installed.
