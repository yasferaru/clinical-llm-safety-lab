# Schema request from prompt p6 (evals/abstention.py, docs/abstention.md)

`check_cases.py` already validates `determinability` and `missing_info_hypotheses`. I changed none of the owner files.

## 1. Results tables (`evals/run_eval.py`, `evals/results.py`)

`abstention.py` works on a DataFrame with one row per (case, epoch). The sample table needs these columns
(nullable; `run_eval.py` copies `determinability` already via `OPTIONAL_META` but they do not reach the table):

| Column | Type | Source |
|---|---|---|
| `response` | str | the scored reply (also requested in `p3.md`) |
| `determinability` | `determinable` / `undeterminable` / null | case field |
| `missing_info_hypotheses` | list | case field (strings or dicts, see 2) |
| `confidence` | float in [0, 1] or null | verbalized confidence, see 4 |

## 2. Hypothesis likelihood flag

Allow each item of `missing_info_hypotheses` to be a string **or** a mapping `{text: <str>, unlikely: <bool>}`.
Validation: `text` non-empty; `unlikely` optional bool (default false). Why: hypothesis coverage should report the
unlikely-but-action-changing hypotheses separately, which is the point of the check. `abstention.py` already accepts
both forms.

## 3. Optional `hypothesis_actions`, to make determinability checkable

New optional field, a list of `{hypothesis: <text>, safe_action: <short text>}`. Validation: every `hypothesis` equals an
item of `missing_info_hypotheses`; if `determinability: undeterminable`, at least two distinct `safe_action` values;
if `determinable`, all `safe_action` values identical. This turns the labelling procedure in `docs/abstention.md`
into a consistency check instead of a convention, and lets two labellers' disagreements be found automatically.

## 4. Confidence elicitation

If selective-prediction results are wanted, the model prompt must ask for a confidence in [0, 1], and the harness
must store it (e.g. as a `confidence` key in the score metadata). This is a change to `run_eval.py` and to the prompt, so
it is a decision for its owner. Without it `selective_report` returns None.

## 5. Consistency checks for `check_cases.py` (cross-field)

- `determinability: undeterminable` should have `expected_safe_stance: ask_for_more_info`; `determinable` should not.
- Undeterminable cases: at least 2 hypotheses (one hypothesis cannot change the action).
- A `control` record should not have `determinability: undeterminable`.
- Warn when a benign control or determinable case has a critical `must` line that rewards asking.

## 6. Data

No case in `evals/cases/` has `determinability` yet, so every abstention metric currently has an empty denominator.
Needed: labelled undeterminable cases (with hypotheses), determinable cases, and benign controls, in a roughly balanced mix.
