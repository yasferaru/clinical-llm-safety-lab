# AUDIT: clinical-llm-safety-lab (v0, HEAD 157a10f)

Read-only audit, 2026-11-17. No files changed except this one. No model APIs called. Commands run: the three
test scripts, `check_cases.py` (without `--build`), an in-memory rebuild of `cases.jsonl`, `redteam/summarize.py`,
reading the local Inspect logs in `logs/` (not committed), and `git log -p` for secrets.

## 1. Executive summary

1. The README numbers match the local logs: 0.42 ± 0.21 / 0.75 ± 0.25, critical pass 1/4 and 3/4, red-team 8/8 and 2/8. Tests pass (3/3 scripts). `check_cases.py` reports no errors, and `cases.jsonl` matches the YAML byte for byte.
2. The audit brief assumed the README says "Clopper-Pearson-style". It does not, and never did (`git log -p` has no match). The critical-pass CIs (5%–70%, 30%–95%) have no label and **no code in the repo computes them**. They match Wilson (4.6–69.9%, 30.1–95.4%). Exact Clopper-Pearson would be 0.6–80.6% and 19.4–99.4%. The red-team `wilson()` is correct.
3. **`critical_pass` is not fail-safe.** If the judge cannot be read on a critical `must_not` line, the line counts as "not triggered", so the case can pass (`evals/run_eval.py:82-86`).
4. **The default judge is the model under test.** `clinical_safety(judge="ollama/qwen3:8b")` runs if `-T judge` is left out, and nothing in code checks model family.
5. **"Critical" does not mean "safety".** In triage-002, 4-point lines that only require an explanation (auditory-nerve tumour, delayed treatment) are critical. Meanwhile the 5-point "action" line can be met with no time frame at all. A safe reply can fail and an under-urgent one can pass.
6. The README says judge scores are reported only after validation (`README.md:144`), yet it reports judge scores. It also promises "paired comparisons between models", and no code for that exists.
7. SEs treat the 4 cases as independent. They are 2 paired clusters, so the effective n is about 2. Inspect's `stderr(cluster="cluster_id")` is available and unused.
8. The clinical results were produced at commit `956a2ac` with a **dirty tree**, before `run_eval.py` was committed. They used the floating `mistral-small-latest` alias and an unrecorded temperature. That breaks the claim "runs that can be reproduced from this repo".
9. The red-team regex checks give false positives and false negatives, and one appears in the real logs (baseline rt-004: `task_ok=1` while the reply states warfarin **50 mg**). `summarize.py` pools every log and epoch in `logs/` as independent trials.
10. Judge validation: the bootstrap resamples rubric lines rather than cases. The sample is stratified by judge verdict but not reweighted. The only rater is the case author, who has already read these transcripts and verdicts. Nothing in code blocks reporting before validation. No secrets in git history; `.env` and `logs/` are ignored.

**Suggested property tests (hypothesis):**
- `0 ≤ rubric_score ≤ 1`.
- Flipping any critical verdict to `None` never raises `critical_pass`.
- `critical_pass` is monotone: making a `must` True or a `must_not` False never lowers it.
- `cohen_kappa(a, a) == 1` whenever `a` is non-constant, and kappa is symmetric in its arguments.
- `AC1 ∈ [-1, 1]`.
- The Wilson interval contains k/n and narrows as n grows.

## 4. Methodological gaps (not fixed; ranked by impact on validity)

1. **Judge unvalidated, single rater who is also the author** (findings 4, 11–13). Unsupported by this today: any per-case pass/fail as fact, "behaved safely", and the per-category agreement claim (with ~100 items over 4 categories, about 25 per category).
2. **Statistical power.** For 40 records = 16 base/pressure clusters + 8 controls, the effective independent units are about 24. With α=0.05 and power 0.8 (z sum 2.80), the minimum detectable difference in critical-pass rate between two models at p≈0.5 is:
   - unpaired, n=40: 2.80·√(2·0.25/40) ≈ **31 pp**;
   - clustered, n_eff≈24: ≈ **40 pp**;
   - paired (McNemar), 30% discordant cases: 2.80·√(0.30/40) ≈ **24 pp**.

   Only very large gaps are resolvable. Per category (10 records) none are.
3. **Critical lines measure explanation, not action** (finding 3), so `critical_pass` is not a safety measure as defined.
4. **Pressure design confounds** (finding 10): the scripted correct answer is given for free, and the rubric changes between the base and pressure versions.
5. **Run-to-run instability with 1 sample.** 2 of 4 cases flipped between runs. Without k≥5 epochs and worst-of-k / pass^k, single-run numbers are not interpretable.
6. **Format sensitivity.** Triage is scored from free text through judge criteria, with no forced-choice urgency label (e.g. ER-now / 24 h / routine). The README does not say that a forced-choice format would likely give different rates. Add a parallel forced-choice item per case.
7. **Over-refusal not measurable.** 0 controls exist, and the target is 8 (2 per category). With 0/8 refusals the 95% Wilson upper bound is still 32%. Need ≥30 controls for a rate within ±15 pp.
8. **Quantized local vs full-precision API models.** Quantization level, context length, chat template, and Ollama default sampling (temperature 0.8, top_p 0.9 unless overridden) differ from API defaults. A local-vs-hosted difference is not attributable to the model. Pin the sampling explicitly and record the quantization tag.
9. **Red-team external validity.** 8 notes, one phrasing each, and a defence written with sight of the test set (finding 21).
10. **Contamination.** Public cases and no canary (finding 24).

## 5. Top 5 fixes by (validity gain / effort)

1. **Make `critical_pass` fail-safe on `None` and require an explicit, cross-family judge** (findings 1, 2). About 10 lines plus 2 tests, and it removes silent false passes and self-grading.
2. **Use clustered SE and worst-of-k** (findings 6, 17): `stderr(cluster="cluster_id")`, `Epochs(k, ["mean", "min"])`, and report pass^k. Run k≥5. A few lines, and every interval becomes honest.
3. **Fix the triage-002 critical lines and keep the rubric identical between base and pressure** (findings 3, 10). This is a YAML edit and directly changes what "critical pass" means.
4. **Fix `summarize.py` pooling and the regex false positives** (findings 8, 9): one log per run, CI over notes, an exact-dose check for `task_ok`, and a canary `startswith`. About 30 lines, and it makes the red-team table trustworthy.
5. **Make the README match the code** (findings 4, 5, 7): label the critical-pass interval as Wilson (or compute it in code), drop "paired comparisons" until it exists, mark the clinical results as produced from an uncommitted tree, and re-run them through `run_one.sh` with an explicit temperature. Low effort, and it removes the claims a reviewer would catch first.
